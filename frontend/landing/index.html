Guardrails

Six safety checks the model can't talk its way past

Each one runs in code outside the LLM, before any PayPal call is made.

Exact decimal math

Fees and discounts run as parsed Python Decimal expressions. No floating point, no model math.

Spend policy engine

Caps and approval lines are enforced in Go right before each mutation, not suggested in a prompt.

Capability registry

Agents only call tools you've allowed, like paypal_refund_capture. Made-up APIs fail to compile.

Cycle detection

Every agent compiles to a directed graph. A loop fails the build, so a run can't repeat a payment.

PII redaction

Card numbers, tokens and auth headers are stripped before they reach prompts, traces or logs.

Idempotent execution

Each money call carries a PayPal-Request-Id and a Redis lock, so retries never double-charge.

Questions, answered

Something missing? Email the team.

Does DelTix move real money?

Not by default. Every workspace starts on the PayPal Developer Sandbox. Live payments only start after you connect a live PayPal account and deploy an agent that passed its pre-flight tests.

What happens if the model gets it wrong?

The model can only propose actions. Spend caps, approval lines and allowed tools are checked in deterministic code before each call. A bad proposal is blocked and logged, not executed.

Which LLMs does it use?

The compiler and runtime use Gemini with an automatic fallback across models. Arithmetic never goes through a model.

Can my auditors use the ledger?

Yes. Every event is append-only with a SHA-256 checksum and the PayPal idempotency key. Export to CSV or PDF for SOC 2, PCI-DSS or ISO 27001 reviews.

How long does setup take?

Sign in with Google and your workspace is created automatically. From there you can compile your first agent and test it in the sandbox in one sitting.
